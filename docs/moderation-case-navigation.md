# Current moderation case navigation

The environment-scoped moderation consumer uses the existing fixed durable and stream with exactly two filter subjects: `moderation-v2.<environment>.report.ready-for-review` and `moderation-v2.<environment>.case.restructured`. Legacy V1 remains isolated. Stage and Production activation retain their existing independent gates; infrastructure provisions Stage only.

V7 preserves notification, action, recipient and delivery history. Immutable typed structure chunks contain only report/capture identities, current membership, revisions and a globally ordered structure sequence. No note, reason, evidence content or reporter identity crosses NATS. All chunks must commit before current navigation changes; an incomplete operation is retried through the existing durable. Conflicting identities terminate safely. Receipt replays skip audience resolution after verifying the original fingerprint.

An environment-wide transaction lock serializes graph changes against ordinary readiness and inbox materialization. Current report membership converges using the greatest structure sequence, including out-of-order ready/merge/split delivery. Capture facts never regress. Existing actions resolve the current report location and flat case leader at read time without rewriting stored historical actions. Source recipients are archived through the existing audience-change/live outbox; only current ready cases have active canonical notifications. Newly eligible staff gain the current case, never archived historical entries. Case mutations, risk, findings and sanctions remain the Moderation Service's responsibility.

Deployment order: extend the existing Stage stream and exact producer/consumer ACLs, deploy this compatible consumer to all Notifications instances, verify its two-subject durable configuration, and only then activate a Moderation producer that can emit structure events. During a rolling deployment, an older consumer could reconfigure its durable to a single subject; confirm all old instances have stopped before producer activation. Do not activate Production or the legacy producer as part of this change.

Verification includes actual PostgreSQL concurrency and rollback tests, strict payload validation, real authenticated NATS durable upgrades preserving ACK history, and `ci/verify-native.py` against two packaged production processes sharing PostgreSQL and NATS. The packaged contract covers live retirement, Portal inbox and remote Minecraft pull after merge/split, replay and V1/Production isolation. It is automated acceptance, not a human in-game confirmation.
